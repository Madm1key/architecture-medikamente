# Task 1: Анализ безопасности системы «Медикаменте»

## 1. Анализ процессов и потоков данных (As-Is)

### Процесс 1: Регистрация пациента

**Задействованные данные:** PII_BASIC, PII_EXTENDED

Текущий поток:

1. Пациент устно или письменно передает данные сотруднику ресепшена.
2. Сотрудник вручную вносит данные в Excel-файл на общем сетевом диске.
3. Запись на прием вносится в журнал записей (Excel).
4. Данные хранятся на общем диске - доступны всем пользователям домена.

**Проблемы процесса:** нет шифрования, нет разграничения доступа, нет аудита.

---

### Процесс 2: Медицинская консультация

**Задействованные данные:** PII_BASIC, SPD_HEALTH, SPD_LAB

Текущий поток:

1. Врач открывает медицинскую карту пациента с общего диска (Excel или скан).
2. Просматривает предыдущие результаты анализов (PDF/JPG).
3. Проводит консультацию.
4. Вносит новые записи в медицинскую карту и сохраняет файл на общем диске.

**Проблемы процесса:** нет шифрования, нет разграничения доступа, нет аудита.

---

### Процесс 3: Обработка платежей

**Задействованные данные:** FINANCIAL, PII_BASIC

Текущий поток:

1. Пациент оплачивает услуги на кассе.
2. Кассир проводит оплату через ККМ (соединение TCP/IP → сервер → 1С через OLE).
3. Параллельно кассир вносит данные в Excel (двойной учет).
4. Бухгалтерия ведет 1С:Бухгалтерия, интегрированную с 1С:Торговля и склад.

**Проблемы процесса:** TCP/IP без шифрования, дублирование данных в Excel и 1С.

---

### Процесс 4: Лабораторные анализы

**Задействованные данные:** PII_BASIC, SPD_HEALTH, SPD_LAB

Текущий поток:

1. Врач выписывает направление на анализы (данные пациента + медицинское показание).
2. Данные пациента и направление передаются во внешнюю лабораторию (способ - не определен).
3. Лаборатория возвращает результаты в виде файлов (PDF/JPG/скан).
4. Файлы сохраняются на общем сетевом диске без структурированной папки.
5. Врач открывает файлы с диска напрямую.

**Проблемы процесса:** передача ПД во внешнюю организацию, хранение без контроля.

---

### Процесс 5: Аналитика и отчетность

**Задействованные данные:** все категории без фильтрации

Текущий поток:

1. Бизнес-аналитик самостоятельно выгружает данные из Excel-файлов на общем диске.
2. Обрабатывает данные в Python (локально или без контроля среды).
3. Формирует отчеты: P&L, ABC-анализ и др.
4. Сохраняет отчеты в файлы для передачи руководству.

**Проблемы процесса:** в аналитику попадают необезличенные ПД и медицинские данные, нет data
lineage.

---

## 2. Список проблемных зон

### 2.1 Отсутствие шифрования данных

1. Медицинские карты, анализы, ПД хранятся в незашифрованных Excel/PDF/JPG на общем диске.
2. Персональные данные передаются без шифрования (нет TLS между рабочими местами и сервером).
3. ККМ передают транзакционные данные на сервер по TCP/IP без шифрования.

### 2.2 Отсутствие контроля доступа

1. Единственный контроль доступа - доменная аутентификация AD; нет ролевого разграничения.
2. Все сотрудники с доменной учеткой имеют доступ к общему диску со всеми данными.
3. Нарушен принцип минимальных привилегий: кассир может читать медицинские карты.
4. Врач видит медицинские карты всех пациентов, включая пациентов других врачей.

### 2.3 Отсутствие аудита и мониторинга

1. Не ведутся журнал аудита доступа к данным пациентов.
2. Нет алертов о нетипичных действиях.
3. Нет системы предотвращения утечек данных (DLP).

### 2.4 Риски ручной обработки данных

1. Ручной ввод данных - риск ошибок и случайного раскрытия через экран/бумагу.
2. Excel-файлы не имеют контроля версий, история изменений не восстанавливается.
3. Дублирование данных в Excel и 1С создает риск несогласованности и лишних копий ПД.

### 2.5 Отсутствие контроля внешних потоков данных

1. Данные пациентов передаются в лабораторию без шифрования.
2. Нет контроля над тем, что выгружается для построения отчетов.
