# Стратегия защиты данных (Data Protection Strategy)

## 1. Стратегия шифрования и инструменты защиты

Ниже представлена таблица с классификацией данных, обоснованием необходимости их защиты и
предлагаемыми инструментами.

| Категория и тип данных                                                                        | В чём необходимость защиты                                                                                                                                  | Инструменты защиты                                                                            |
|:----------------------------------------------------------------------------------------------|:------------------------------------------------------------------------------------------------------------------------------------------------------------|:----------------------------------------------------------------------------------------------|
| **Данные при передаче (Data in Transit)**                                                     |                                                                                                                                                             |                                                                                               |
| **Все данные** (между клиентом и системой, между сервисами)                                   | Защита от перехвата и атак "man-in-the-middle" (MitM) при передаче по общедоступным и внутренним сетям. Соответствие требованиям безопасности.              | Обязательное использование HTTPS для всего внешнего трафика (порталы для пациентов и врачей). |
| **Данные при хранении (Data at Rest)**                                                        |                                                                                                                                                             |                                                                                               |
| **Специальные категории** (диагнозы, история болезни, результаты анализов, заключения врачей) | **Высокий риск.** Это наиболее чувствительная информация. Утечка может нанести серьезный вред репутации и привести к юридической ответственности по ФЗ-152. | Шифрование хранилища данных (здесь и далее использование KMS для хранения и ротации ключей).  |
| **Персональные данные** (ФИО, дата рождения, паспорт, контакты, адрес)                        | **Высокий риск.** Прямая идентификация личности. Требуется защита в соответствии с ФЗ-152. Утечка ведет к репутационным и финансовым потерям.               | Шифрование хранилища данных.                                                                  |
| **Финансовые данные** (информация о платежах, счетах)                                         | **Средний риск.** Защита от мошенничества и обеспечение финансовой конфиденциальности.                                                                      | Шифрование хранилища данных.                                                                  |
| **Файловые хранилища** (сканы договоров, медицинских документов в PDF/JPG)                    | **Высокий риск.** Файлы содержат смесь персональных и медицинских данных.                                                                                   | Шифрование хранищила данных.                                                                  |

## 2. Автоматизированный контроль и мониторинг

| Средство контроля              | Описание                                                                                                                                | Инструменты                                                                                                    |
|:-------------------------------|:----------------------------------------------------------------------------------------------------------------------------------------|:---------------------------------------------------------------------------------------------------------------|
| **Аудит доступа к данным**     | Централизованная запись всех событий доступа к конфиденциальным данным: кто, когда, к каким данным обращался и какие действия выполнял. | Использование систем для агрегации, анализа логов и выявления аномалий (например, массовое скачивание данных). |
| **Data Loss Prevention (DLP)** | Системы для предотвращения утечек данных путем мониторинга и контроля за их перемещением.                                               | Тегирование данных и проведения сканирования контета.                                                          |
| **Управление уязвимостями**    | Регулярное сканирование кода и инфраструктуры на наличие уязвимостей.                                                                   | Анализ исходного кода; проверка зависимостей.                                                                  |
